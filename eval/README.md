# 평가

## 1. 평가 구성

평가는 두 층으로 나눈다. 숫자는 결정론적 도구가 계산하고 에이전트는 도구를 고르고 결과를 설명하므로, 두 층이 서로 다른 책임을 확인한다.

| 층 | 확인 대상 | 기준 | 실행 모듈 |
|---|---|---|---|
| 점검표 | CAD 파싱, 개정 diff, 분석 도구, 레이아웃 엔진이 계산한 값 | 생성기의 정답 도면·변경 목록과 업무 데이터에 심어 둔 효과 | `cad2anything.evaluation.scorecard` |
| 에이전트 평가 | 에이전트의 도구 선택, 화면 제어, 답변의 핵심 사실, 데이터 경계 | 한국어 골든 질문(`eval/golden/agent_questions.yaml`)의 규칙 | `cad2anything.evaluation.agent_eval` |

## 2. 점검표

**실행**

```powershell
uv run --no-sync python -m cad2anything.evaluation.scorecard --root data/workspace --truth data/generated/truth
```

하나라도 `실패`이면 종료 코드 1을 반환한다. 파싱 모델이나 정답 파일이 없는 항목은 `건너뜀`으로 표시한다.

**항목**

| 점검 | 통과 기준 |
|---|---|
| 개정별 도면 파싱 정확도 | 매장 정밀도·재현율과 브랜드 ID 정확도가 모두 0.98 이상 |
| 개정 diff 정확도(R0→R1, R1→R2, R2→H1) | 변경 항목 정밀도·재현율이 모두 0.95 이상 |
| 저효율 존 회수 | R2 4층 하위 10% 플래그에 4F-E01~E06 중 3개 이상이 포함 |
| 세그먼트 교차구매 회수 | 40대 VIP·VVIP 여성의 화장품↔명품·해외패션 lift가 2.0 이상이고, 20대보다 0.5 이상 높음 |
| 노출 함정 판정 | 아동 매장 근처 효과가 노출 통제 후 줄어들고, 공통 원인 의심으로 판정 |
| 분수·샤워 흐름 회수 | B1 구매자의 같은 날 위층 구매 비율이 0.3 이상이고, 최상층 구매 다음 구매가 아래층일 확률이 0.6 이상 |
| MD 개편 효과 회수 | R1에 에스컬레이터 정면으로 옮긴 브랜드의 전후 변화가 같은 층 비교군보다 큼 |
| 레이아웃 대안 제약 충족 | 4층 대안이 모든 제약을 지키고 기대 매출이 증가 |

**2026-10-21 실행 결과(시드 42, 표본 비율 0.02, 파싱 모델 기준):** 13개 항목이 모두 통과했다.

- 도면 파싱: 4개 개정 모두 매장 정밀도·재현율과 브랜드 ID 정확도가 1.0이었다.
- 개정 diff: 세 구간(19건, 9건, 3건) 모두 정밀도·재현율이 1.0이었다.
- 교차구매 lift: 대상 세그먼트 3.13, 20대 1.46이었다.
- 노출 함정: 단순 비교 +18.8%가 노출 통제 후 +3.3%로 줄었다.

## 3. 에이전트 평가

**전제조건**

- 에이전트가 배포되어 있다(`infra/README.md` 4단계).
- `FOUNDRY_PROJECT_ENDPOINT`가 설정되어 있다.
- 히트맵 값을 계산할 작업공간이 있다. 기본값은 `data/workspace`다.

**실행**

```powershell
uv run --no-sync python -m cad2anything.evaluation.agent_eval --cases eval/golden/agent_questions.yaml
```

특정 사례만 실행하려면 `--only rev-ss-changes,prod-4f-low`처럼 사례 ID를 지정한다. 결과는 `eval/results/`에 JSON으로 저장한다. 이 폴더는 모델 답변을 담으므로 커밋하지 않는다.

**점검 유형**

| 유형 | 통과 조건 |
|---|---|
| `tools_any`, `tools_all`, `tools_none` | 지정한 도구를 하나라도, 모두, 하나도 호출하지 않음. 전문 에이전트 안의 호출도 포함한다. |
| `ui_any` | 지정한 UI 함수 중 하나 이상으로 화면을 바꿈 |
| `specialists_any` | 지정한 전문 에이전트 중 하나 이상과 상담 |
| `answer_any`, `answer_all`, `answer_none` | 답변에 지정 문구가 하나라도, 모두, 하나도 나오지 않음 |
| `consult_not_regex` | 지정한 전문 에이전트에 넘긴 요청이 정규식(예: 내부 매출 금액)과 일치하지 않음 |

실행 중 오류가 나면 그 사례는 실패로 처리한다.

## 4. 한계

- 규칙 채점은 도구 호출과 핵심 문구만 확인한다. 답변이 도구 결과와 일치하는지는 결과 파일의 답변을 사람이 확인한다.
- 같은 질문이라도 실행마다 도구 선택과 표현이 달라질 수 있다. 데모 전에는 여러 번 실행해 실패 경향을 본다.
- 점검표의 기준은 합성 데이터의 정답이다. 실제 데이터에는 정답이 없으므로 표본을 사람이 검증해야 한다.
- Foundry Evaluation의 LLM 평가자(근거 일치, 도구 호출 정확도)는 아직 연결하지 않았다.
